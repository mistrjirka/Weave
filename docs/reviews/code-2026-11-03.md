# Repository and implementation review · 2026-11-03

## Scope and method

Reviewed tracked source, documentation consumers, exports and worker entry points. A requested `impl-check` skill was not installed; a Luna subagent performed a read-only implementation review instead. Parent review checked its findings against the source and added regression tests. Existing user projects, training scripts and generated data were excluded.

The code uses TypeScript strict mode, React 19, React Flow, Zod, FastAPI, Pydantic, SQLite and PyTorch. The review used their official guidance, plus Knip for frontend reachability, Ruff for unused Python imports/locals and Vulture as a secondary check. These tools report candidates; dynamic exports and subprocesses require manual reference checks.

## Corrections

| Priority | Finding and trigger | Change and regression coverage |
| --- | --- | --- |
| P2 | GPU tuner nested requests could finish after closing/reopening the dialog or starting a different job, replacing current job state. | Lifecycle guards and request versions reject stale job/list/error responses. A deferred-response browser test resolves the obsolete job last. |
| P2 | `with sqlite3.Connection` commits/rolls back but does not close it. Repeated project requests relied on garbage collection to release connections. | The project DB helper explicitly closes connections on success and failure. Tests verify closed handles and rollback. |
| P2 | Tokenizer upload wrote files, listed directories and removed temporary bundles synchronously inside an async endpoint. Slow disks could delay other requests. | The whole blocking upload operation runs as a normal FastAPI endpoint in its threadpool. | P3 | Reporting JSON validation ran on the event loop before ingestion was offloaded. | Parsing/validation now runs in a worker thread too. A regression verifies the validation thread. Payload limits and error handling are retained. |
| P3 | A single-use MCP session manager was reused across ASGI lifespans. Combining independently passing test modules exposed a startup failure. | Create a fresh public MCP HTTP transport per lifespan. Repeated startup tests verify MCP routes on both lifespans. |

No model math or user training scripts were changed by these corrections.

## Remaining work

**P3: retained chat sessions are unbounded.** `ChatSessions.for_run` keeps every visited run's service; idle unload releases model/GPU memory but preserves messages in the process. Long sessions across many runs can accumulate memory. A safe follow-up should persist/reload complete conversations and evict inactive sessions with a documented limit. Do not silently truncate history or discard unloaded conversations merely to satisfy a bound.

`main.tsx` and `TrainingWorkspace.tsx` are large orchestration components. Feature-by-feature extraction is warranted when changing those flows, with tests around the extracted state/lifecycle. File size alone is not evidence of a current correctness bug. A whole-tree rename would add risk without resolving those boundaries.

This was a focused implementation review, not a claim that every concurrency path or neural architecture is proven correct. No blanket replacement of effects, registries or explicit validation is recommended.
