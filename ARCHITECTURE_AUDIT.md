# Reference architecture audit

This is a scoped source comparison, not checkpoint conversion or a proof that each complete product is reproduced. All exports initialize new weights. Padding-aware masks, caches, training recipes, and tokenizers require separate work.

- **Thimble v6 trunk:** the [published model card](https://huggingface.co/flashvenom/thimble) and the pinned source in `references/thimble_model.py` describe 20 layers, 448 hidden features, GQA 8/4, gated attention, sandwich RMSNorm, SwiGLU (SiLU), and tied token embeddings. Tool grammar, retrieval and auxiliary heads are not included. A two-layer, weight-matched float32 trunk produces the same logits as the pinned upstream source. No checkpoint parity is claimed.
- **Hammer 2.1 0.5B:** its [configuration](https://huggingface.co/MadeAgents/Hammer2.1-0.5b/blob/main/config.json) specifies Qwen2 with SiLU, 24 layers, width 896, FFN width 4864, GQA 14/2 and YaRN. The Qwen2 implementation uses biases in Q/K/V but not the output projection. The graph models these settings and ties the vocabulary head. A 24-layer, reduced-width, weight-matched float32 model matches Transformers logits. Full-sequence random-weight computation only; checkpoint loading, padding masks, KV caching, exact initialization, tokenizer and function-calling protocol are outside its scope. YaRN follows the [Transformers 4.45 formula](https://github.com/huggingface/transformers/blob/v4.45.2/src/transformers/modeling_rope_utils.py).
- **SHELLper:** the [published configuration](https://huggingface.co/distil-labs/distil-lfm25-shellper/blob/main/config.json) specifies the 16-layer convolution/attention schedule, width 1024, GQA 16/8 and 65536 vocabulary. The [LFM2 implementation](https://github.com/huggingface/transformers/blob/main/src/transformers/models/lfm2/modeling_lfm2.py) uses double-gated short convolutions and a SwiGLU FFN; its automatic adjustment maps the configured 6656 FFN setting to an actual hidden width of 4608. Weave uses equivalent separate input projections, exposes the operations, and omits caches, padding masks and fine-tuned weights. Parameter count is 354,483,968. A reduced-width, weight-matched 16-layer float32 model matches Transformers logits.
- **Needle 1:** the [pinned model card](https://huggingface.co/Cactus-Compute/needle/tree/5f89b4307696d669c3df1d38ae057e6e1728b107) documents an encoder-decoder attention-only topology, so a feed-forward activation should not be invented. The graph now includes scaled embeddings, encoder output normalization and cross-attention Q/K normalization. A two-layer, weight-matched float32 export matches the historical JAX logits with a causal decoder mask. Padding masks, quantization, pretrained weights and caches are excluded.
- **Needle 2/3:** Weave keeps the previously pinned configs and source under `references/`. The pinned [Needle 2 source](https://github.com/cactus-compute/needle/blob/2e19bab90ca4/needle/model/architecture.py) uses a two-stage Hadamard mixer; Needle 3 uses a learned Monarch mixer. Both graphs include attention, Engram and residual-lane routing. Two-layer, weight-matched float32 exports match their pinned JAX logits, including a short local window and unequal query/value head widths for Needle 3. The Needle 2 reference uses the published deployment window; the historical JAX forward accepts a caller-supplied mask and defaults to full causal attention. Quantization, packed/padding masks, auxiliary heads, trained ladder subnetworks and checkpoint conversion are excluded.
- **GPT-2 small:** the [model configuration](https://huggingface.co/openai-community/gpt2/blob/main/config.json) specifies 12 layers, width 768, 12 heads, learned positions and GELU. The graph includes the tanh GELU approximation, LayerNorm, embedding/attention/residual dropout and tied vocabulary output. It has 124,439,808 parameters, and a two-layer, weight-matched float32 export matches Transformers logits. Checkpoint loading, padding masks and cached inference are not implemented.
- **Synthetic examples:** decoder, MoE, looped and diffusion graphs demonstrate composable blocks. They are not checkpoint reproductions. Their SwiGLU is an explicit example design choice rather than an assertion that all transformers use it.

GELU is common in other architectures, but these particular cited trunks predominantly use SiLU-based gating, different mixers, or no FFN. The library now includes GELU, ReLU, LayerNorm, dropout, learned positional embeddings, convolution and pooling for broader designs. These operations have shape, parameter-count and forward/backward export tests. Numerical checks use smaller widths and synthetic weights; comparison against actual pretrained checkpoints remains future work.
